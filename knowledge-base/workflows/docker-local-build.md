# Running Slate Locally with Docker

Docker is the recommended way to build and preview these docs locally. It avoids
installing Ruby 2.6 / Bundler 2.4.22 natively, which is the only combination the
`Gemfile.lock` is pinned against.

The repo `README.md` is the stock upstream Slate readme and only links to the
upstream wiki. The steps below are the project-specific ones, verified against
this repo.

## Build the image

```bash
docker build . -t slate:local
```

Takes ~2 minutes cold. The `Dockerfile` installs gems in a layer before
`COPY . /srv/slate`, so editing docs does not invalidate the `bundle install`
layer — rebuilds after a content change are near-instant.

## Build the static site

```bash
mkdir -p build
docker run --rm \
  --user "$(id -u):$(id -g)" \
  -v "$(pwd)/build:/srv/slate/build" \
  slate:local
```

Output lands in `build/` (gitignored). `build` is the image's default `CMD`, so
no command argument is needed. This runs `middleman build --clean`.

> ⚠️ **Always pass `--user`.** Without it the container runs as root and every
> file in `build/` ends up root-owned. Because the generated subdirectories
> (`build/fonts`, `build/stylesheets`, ...) are then root-owned too, a later
> `rm -rf build` or `middleman build --clean` fails with `Permission denied` and
> needs `sudo`. To recover from an already-root-owned `build/`:
>
> ```bash
> docker run --rm -v "$(pwd)/build:/b" alpine sh -c 'rm -rf /b/* /b/.[!.]*'
> ```

## Serve with live reload

```bash
docker run --rm --name slate-serve \
  -p 4567:4567 \
  -v "$(pwd)/source:/srv/slate/source" \
  slate:local serve
```

Then open <http://localhost:4567>.

- Mounting `source/` is what makes live reload work. Without the mount you are
  serving the copy baked into the image at `docker build` time, and edits do
  nothing.
- `slate.sh` already passes `--watcher-force-polling`, which is required for
  file-change detection across a bind mount. Expect a **~10 second** delay
  between saving a file and the change appearing — polling is not instant.
- Startup takes a few seconds. Wait for
  `== View your site at "http://localhost:4567"` in the logs before curling, or
  the first request fails with a connection error.
- Stop with `docker rm -f slate-serve`.

## Verifying a docs change

After building, check the rendered output rather than trusting the source diff:

```bash
grep -c "YourNewText" build/index.html
```

Internal anchors are generated by `lib/unique_head.rb`, which emits
**single-quoted** `id='...'` attributes. Any link-checking script must match both
quote styles or it will report every anchor as broken. Duplicate heading text
gets a numeric suffix (`#headers`, `#headers-2`, ...), so adding or removing a
heading can silently renumber anchors that other sections link to.

## Known warnings (harmless)

- `Your RubyGems version (3.0.3.1) has a bug that prevents required_ruby_version...`
- `Sprockets will render css with ruby sass / consider using Sprockets 4.x`

Both are emitted on every run and do not indicate a problem.
